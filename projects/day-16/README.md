# День 16. Подключение MCP

Агент Дня 6 получает инструмент чтения файла у официального Filesystem MCP Server.
В первом сценарии агенту нужно узнать учебный курс из файла. Во втором нужно
прочитать курс и пересчитать 237 долларов в рубли локальным калькулятором Дня 6.

## Запуск

Потребуются Python 3.10 или новее, Node.js 22 или новее с npx и ключ Polza.ai
в переменной POLZA_API_KEY либо в корневом файле .env. Команды из корня проекта
для Python 3.12:

```bash
python3.12 -m venv projects/day-16/.venv
source projects/day-16/.venv/bin/activate
python -m pip install -r projects/day-16/requirements.txt
python projects/day-16/main.py
```

При первом запуске npx скачивает готовый пакет
`@modelcontextprotocol/server-filesystem`. Сервер работает отдельным процессом
и получает каталог `projects/day-16/data` как рабочий и разрешённый каталог.

## Как работает

Разберём вопрос «Сколько рублей стоят 237 долларов по курсу из rates.txt? Для расчёта воспользуйся калькулятором». Python-агент ведёт диалог с моделью через HTTPS и общается с отдельным процессом Filesystem MCP Server через стандартные потоки ввода и вывода (stdio). Калькулятор работает внутри самого Python-процесса.

**До вопроса.** Python запускает сервер через `npx` и передаёт ему путь к разрешённому каталогу `projects/day-16/data`. Вызов `session.initialize()` открывает сессию, а `session.list_tools()` получает каталог инструментов. Из каталога агент берёт описание `read_text_file`. На этом шаге курс ещё неизвестен.

| Обращение к модели | Что Python передаёт в Polza.ai | Что модель возвращает |
| --- | --- | --- |
| Первое | В `messages` лежат системная инструкция и вопрос с суммой 237. В `tools` лежат описания двух функций. Режим `tool_choice: "auto"` позволяет модели выбрать вызов. | В `tool_calls` приходит имя `read_text_file` и аргумент `{"path":"rates.txt"}`. |
| Второе | Та же история, дополненная просьбой модели прочитать файл и ответом сервера «Учебный курс: 1 USD = 93.75 RUB.». | В `tool_calls` приходит имя `calculate` и аргументы `{"operation":"multiply","a":237,"b":93.75}`. |
| Третье | К истории добавлены вызов калькулятора и его результат `22218.75`. | Текстовый ответ «237 долларов по курсу 93,75 руб. за доллар стоят 22 218,75 рублей». Цикл завершается. |

**Какие параметры видит модель?** В каждом элементе `tools` есть `function.name`, `function.description` и `function.parameters`. Последнее поле описывает допустимые аргументы. Для чтения файла Python берёт эту схему из `inputSchema` MCP-сервера. Для калькулятора использует схему из Дня 6. Конкретные значения, например `"rates.txt"` или `93.75`, модель указывает в поле `function.arguments` своего вызова.

**Кто исполняет вызов?** Метод `Agent.run` читает имя и аргументы из ответа модели и передаёт их в `FilesystemAgent.execute_tool`. Дальше путь зависит от имени.

- **Чтение файла.** Python разбирает строку `arguments` через `json.loads` и передаёт в `session.call_tool` два значения — имя `"read_text_file"` и словарь `{"path": "rates.txt"}`. В коде этот вызов обёрнут в `anyio.from_thread.run`, чтобы синхронный цикл агента мог обратиться к асинхронной MCP-сессии. Файл открывает сервер и возвращает Python текст с курсом.
- **Расчёт.** Для `calculate` вызывается обработчик из Дня 6. Он разбирает аргументы, проверяет их по схеме и выполняет `FUNCTIONS[name](**arguments)`. В словаре `FUNCTIONS` под именем `"calculate"` хранится Python-функция. Оператор `**` передаёт ей значения по именам. В этом прогоне получается обычный вызов `calculate(operation="multiply", a=237, b=93.75)`.

**Как результат попадает обратно в диалог?** После каждого вызова Python сохраняет в `messages` ответ модели с `tool_calls` и добавляет сообщение с ролью `tool`. В `content` записывает результат, а в `tool_call_id` копирует идентификатор вызова из ответа модели. При следующем обращении модель видит, какой вызов вернул курс, а какой — произведение. В сценарии «только MCP» доступно лишь чтение файла, поэтому уже второе обращение заканчивается ответом о курсе.

## Что смотреть в консоли

1. После MCP initialize программа печатает сведения о сервере. Затем запрашивает
   каталог через list_tools и печатает имена инструментов со всех страниц.
2. Перед каждым запросом программа печатает его JSON-тело. В первом сценарии
   в tools должна быть схема read_text_file, полученная у сервера. Во втором
   рядом появляется схема calculate. История каждого сценария начинается заново.
3. В ответе модели видны tool_calls с именами, аргументами и идентификаторами.
   Программа печатает источник и результат каждого вызова. В следующем запросе
   результат виден в messages с ролью tool и соответствующим tool_call_id.
4. Для проверки смешанного сценария проследите, что курс из ответа сервера
   попал в аргументы калькулятора и его результат совпал с финальным ответом.
   При исходном содержимом rates.txt контрольное значение равно 22 218,75 ₽.
   Само по себе совпадение суммы не подтверждает вызовы инструментов.

## Ответы на вопросы задания

- **Как модель различает инструменты?** Оба представлены как функции с именем,
  описанием и схемой аргументов. Поля с протоколом выполнения в запросе нет.
  Модель выбирает функцию по её назначению. Источник определяет Python при
  обработке tool_calls.
- **Что изменилось относительно Дня 6?** Агент устанавливает MCP-сессию через
  stdio, получает описание и inputSchema функции чтения файла и передаёт их
  модели в формате API. Вызов read_text_file отправляется в session.call_tool,
  а calculate исполняется существующим кодом Дня 6. Цикл запросов к модели и
  привязка результатов по идентификаторам общие для обоих дней.
- **Зачем MCP?** Один и тот же клиент может запросить каталог функций готового
  сервера и вызвать их по стандартному протоколу. В этом примере обработку путей
  и чтение файла реализует внешний пакет. Выбор доступных модели функций
  и преобразование их схем в формат API остаются в агенте.

## Результат запуска 25 ноября 2026 года

Сервер представился как `secure-filesystem-server` версии `2.4.0` и вернул
16 инструментов. В каждом сценарии модель запросила `read_text_file` с аргументом
`{"path":"rates.txt"}`. Оба вызова завершились с `isError: false` и вернули
строку «Учебный курс: 1 USD = 93.75 RUB.».

| Задача | Что произошло | Финальный ответ |
| --- | --- | --- |
| Узнать курс | Один вызов MCP, затем текстовый ответ модели | 1 USD = 93.75 RUB |
| Пересчитать 237 USD | После чтения файла модель запросила локальный calculate. Калькулятор умножил 237 на 93.75 и вернул 22218.75 | 237 долларов стоят 22 218,75 рублей |

Во втором диалоге было три ответа модели. Сначала она выбрала чтение файла.
Получив курс, она передала его в калькулятор. Получив произведение, сформулировала
ответ. Пользователь явно попросил использовать калькулятор. Модель выбрала имя
функции и её аргументы в рамках этой инструкции.

В сохранённом логе тела исходящих запросов обрываются внутри пользовательского
сообщения. Ответы модели и результаты инструментов сохранились. Они подтверждают
последовательность вызовов. Содержимое полей tools и tool_call_id исходящих
запросов по этому файлу проверить нельзя.

Отдельно при проверке с установленным сервером агент сформировал и напечатал
полное тело смешанного запроса. Напечатанный JSON совпал с телом, возвращённым
методом build_payload, и содержал обе схемы в tools. Эта проверка выполнялась
локально без обращения к модели.
