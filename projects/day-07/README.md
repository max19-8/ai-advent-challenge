# День 7. Сохранение контекста

Агент дня 6 дополнен сохранением полной истории в `history.json`. После перезапуска
программа загружает сообщения и продолжает тот же диалог. Модель, инструменты
и схема HTTP-запросов прежние: DeepSeek V4 Flash через Polza.ai, учебные курсы валют
и калькулятор, `tool_choice: auto`, reasoning отключён.

## Как работает память

LLM не хранит память о наших предыдущих HTTP-запросах. Контекст создаётся тем,
что приложение передаёт историю в поле `messages` при каждом обращении.

В дне 6 история создавалась заново для каждого вопроса. Здесь она хранится
в `Agent.messages` и сохраняется на диск:

1. При создании `Agent` загружается `history.json`. Если файла нет или указан
   `--new`, создаётся история с одним системным сообщением.
2. Новый вопрос добавляется в историю и сохраняется.
3. Если модель запросила инструменты, агент выполняет функции и сохраняет
   сообщение `assistant` с `tool_calls` вместе со всеми сообщениями `tool`.
4. Финальное сообщение `assistant` также добавляется в историю и сохраняется.
5. При следующем запуске новый вопрос отправляется вместе с загруженной историей.

Файл содержит весь массив `messages`, а не пересказ разговора:

```text
system: правила поведения
user: имя, сумма в долларах и просьба конвертировать
assistant: вызов get_exchange_rate
tool: курс 90 с соответствующим tool_call_id
assistant: вызов calculate
tool: результат 22500 с соответствующим tool_call_id
assistant: ответ пользователю
user: следующий вопрос после перезапуска
...
```

Сохраняются исходные сообщения модели, включая текст, вызовы функций и аргументы.
Результаты функций остаются в сообщениях `tool`; `tool_call_id` связывает их
с вызовами. Схемы `tools` приложение передаёт заново в каждом HTTP-запросе.
Ключ API берётся из общего `.env`, в историю не записывается.

Запись производится во временный файл с последующей заменой `history.json`.
Сообщение с вызовами инструментов сохраняется вместе с полным набором результатов,
чтобы после перезапуска не осталось вызова без ответа. Повреждённая история
не заменяется молча: программа сообщает об ошибке. Для очистки предусмотрен `--new`.
Один файл предназначен для одного диалога и последовательных запусков.

## Что изменено в коде

| Часть | Что сделано |
| --- | --- |
| `Agent.__init__` | Принимает путь к истории и флаг нового диалога; загружает JSON или создаёт начальное системное сообщение |
| `Agent.messages` | Хранит полный контекст между вызовами `run`, вместо локального списка для каждого вопроса |
| `Agent.validate_history` | Проверяет структуру загруженных сообщений и наличие результатов для всех вызовов инструментов |
| `Agent.save_history` | Записывает весь список во временный `history.json.tmp`, затем заменяет основной файл |
| `Agent.run` | Дополняет и сохраняет историю после вопроса, полного раунда инструментов и финального ответа |
| `main` | Выбирает зашитый вопрос через `--stage`, передаёт `--new` агенту, сохраняет вопрос и ответ в текстовый файл |

При восстановлении используется сохранённое сообщение `system`; оно не добавляется
повторно перед каждым новым вопросом. После загрузки агент передаёт весь список
в `messages` следующего API-запроса. Ключ авторизации и HTTP-заголовки в этот список
не входят. JSON выбран вместо SQLite: для одного небольшого диалога достаточно
одного файла, который можно открыть и проверить вручную.

## Запуск

Из корня репозитория с `POLZA_API_KEY` в существующем `.env`:

```bash
cd ~/Projects/ai-advent-challenge
source .venv/bin/activate
```

Первый запуск с чистой историей:

```bash
python projects/day-07/main.py --stage 1 --new
```

Зашитый вопрос: «Меня зовут Максим. Я откладываю 250 долларов на поездку.
Переведи эту сумму в рубли по учебному курсу».

После завершения программы запускаем новый процесс с продолжением:

```bash
python projects/day-07/main.py --stage 2
```

Второй вопрос: «Как меня зовут, сколько долларов я откладывал и сколько рублей
получилось? Прибавь к полученной сумме ещё 1500 рублей».

Оба запуска выполняют по одному вопросу и завершаются. Вводить текст не нужно.
Результаты дописываются в `results.txt` обычным текстом «вопрос — ответ»;
при ошибке вместо ответа записывается её описание. Демонстрационный вывод
в консоль перед публикацией удалён.

## Контрольный запуск без истории

После двух основных запусков можно выполнить тот же второй вопрос с новым контекстом:

```bash
python projects/day-07/main.py --stage 2 --new
```

`--new` **заменяет прежнюю историю новым диалогом**. Результаты в `results.txt`
сохраняются и дополняются новым ответом. Если нужно сначала осмотреть полную историю
основного диалога, открой `history.json` до контрольного запуска.

Без `--new` используется существующая история; если её ещё нет, начинается новый
диалог. Сам номер этапа не добавляет данные первого вопроса: второй этап знает
имя и прошлые суммы только из загруженных сообщений.

## Что проверяем

| Запуск | Ожидаемое поведение |
| --- | --- |
| `--stage 1 --new` | Модель получает курс инструментом и конвертирует 250 USD в 22 500 RUB |
| `--stage 2` | Восстанавливает имя Максим, исходные 250 USD и результат 22 500 RUB; прибавляет 1500 калькулятором и получает 24 000 RUB |
| `--stage 2 --new` | Не имеет сведений об имени и прошлых суммах; ожидаем запрос уточнения вместо выдуманных данных |

Второй вопрос сам по себе не содержит ни имени, ни исходной суммы, ни результата
конвертации. Поэтому проверяем не только новый расчёт, но и восстановление этих
трёх фактов. В `history.json` после второго запуска должны остаться сообщения
первого этапа, включая `tool_calls`, результаты и связи `tool_call_id`.

## Выводы

- **Контекст сохраняется между процессами.** После завершения первого запуска
  второй восстановил факты разговора и продолжил вычисления с прошлого результата.
- **Сохраняются и действия агента.** В JSON остались не только финальные ответы,
  но и `tool_calls`, аргументы, результаты и связи между ними.
- **Память обеспечивается приложением.** Один и тот же вопрос с восстановленной
  историей получил конкретный ответ, а с `--new` — просьбу уточнить данные.
  Модель не сохраняла сведения независимо от переданных `messages`.
- **Начало нового диалога работает.** В контрольном запуске модель не подставила
  выдуманные имя и суммы и не стала вызывать калькулятор без исходных данных.
- Проверен один диалог и один контрольный запуск. Этот результат не доказывает
  безошибочное использование любой длинной истории.

## Ограничения

История передаётся целиком: по мере роста диалога увеличиваются входные токены.
Сокращение контекста и SQLite в этом задании не используются.

Восстановление проверяется между завершёнными вопросами. При прерывании сохраняются
уже записанные этапы, но автоматического продолжения незавершённого вопроса нет.
История с вопросом, на который не получен ответ, остаётся частью контекста.
Предел — 8 обращений к LLM на один вопрос, таймауты — 10 секунд на соединение
и 180 секунд на чтение, автоматических повторов нет.

`history.json` — рабочая память в JSON по условию задания, `results.txt` — файл
вопросов и ответов для чтения. Это разные форматы для разных задач.
