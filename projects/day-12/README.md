# День 12. Персонализация ассистента

Проверяем, меняется ли сам ответ при одинаковом вопросе и разных пожеланиях пользователей. Вторая проверка показывает, соблюдает ли ассистент один профиль десять ходов подряд.

## Запуск из корня репозитория

Используются окружение и ключ Polza из дня 11. Полный эксперимент запускается одной командой:

```sh
.venv/bin/python projects/day-12/main.py experiment
```

Вводить сообщения не потребуется. Эксперимент каждый раз начинает с пустых профилей, печатает стенограмму в консоль и одновременно дописывает её в `projects/day-12/results.txt`. Завершённый прогон заканчивается строкой «Эксперимент завершён». Если API вернёт ошибку, предыдущие шаги останутся в журнале.

Для свободного диалога используйте `.venv/bin/python projects/day-12/main.py chat`. Команды: `/user Имя` выбирает или создаёт пользователя, `/profile` показывает его текущие предпочтения, `/task Имя` переключает задачу, `/new` очищает короткую историю, `/exit` завершает программу. Состояние чата сохраняется в `state/profiles.json`, журнал — в `state/chat.txt`. Для установки зависимостей в новом окружении: `python -m pip install -r projects/day-12/requirements.txt`.

## Как профиль попадает в запрос

Команда `/user Максим` выбирает в `Profiles.users` отдельный экземпляр `PersonalizedMemory` со своими фактами, задачами и историей. Допустим, Максим пишет: «Обычно отвечай без кода».

1. **Запись предпочтения.** В запросе `extract` Qwen предлагает запись `pref.code = "без кода"` и цитату из реплики. Python проверяет наличие цитаты, а запрос `verify` уточняет, подтверждает ли она запись. Подтверждённое значение попадает в словарь `facts` Максима. При изменении пожелания обновляется тот же ключ. После успешного ответа чат сохраняет состояние в `state/profiles.json`.
2. **Сборка запроса.** Когда Максим спрашивает «Как работает кеш?», метод `PersonalizedMemory.messages()` на Python выбирает из его `facts` ключи с префиксом `pref.`, убирает префикс и собирает поле `Предпочтения`. Ниже показан фрагмент последнего сообщения с ролью `user`.

```json
{
  "Вопрос пользователя": "Как работает кеш?",
  "Предпочтения": {"code": "без кода"}
}
```

3. **Генерация ответа.** В запросе `reply` модель получает системную инструкцию учитывать предпочтения, историю и сообщение с вопросом. Разовая просьба «только сейчас покажи код» имеет приоритет на текущий ход. Python передаёт сгенерированный текст пользователю как есть. Поэтому даже при верном профиле в запросе модель может нарушить ограничение. В журнале строку «Профиль в запросе» можно сопоставить с фактическим ответом.

## Эксперимент

1. А задаёт обычным сообщением обращение на «ты», ограничение в 70 слов и ответы без кода. Б просит обращение на «вы», подробное объяснение принципа и пример на Python. После записи короткая история очищается. Оба получают один и тот же вопрос о выборе между списком и множеством. Итог — количество полностью соответствующих ответов из двух.
2. А начинает свежий диалог и получает десять вопросов подряд. Внутри серии сохраняются обычная история и профиль; вопросы не повторяют пожелания. Отчёт содержит оценку каждого хода, число полных соответствий и номер первого наблюдаемого нарушения. Нарушение в одном ответе не доказывает, что все следующие тоже нарушат предпочтения.
3. Б просит разовый ответ без кода, затем получает обычный вопрос. Проверяем и состояние профиля, и оба ответа. После постоянной просьбы отказаться от кода история очищается и задаётся ещё один вопрос. Эти ходы выводятся отдельно от сравнения и серии.

Лимит слов считается локально (последовательности букв или цифр, допускаются внутренние дефисы и апострофы). Тон, наличие и уместность кода, содержательность объяснения оценивает отдельный запрос к той же Qwen с вопросом, ответом и заранее заданными критериями. Он не видит историю и не меняет память. Для каждого признака в отчёте есть оценка, обоснование и поле цитаты. Отсутствие явного обращения трактуется как «неясно». Если хотя бы один критерий имеет оценку «нет», ответ получает «нарушено»; при одних «да» — «соблюдено»; в остальных случаях — «не подтверждено». Автоматические оценки можно перепроверить по сохранённым текстам.

## Проверка без API

```sh
.venv/bin/python projects/day-12/test_personalization.py -v
```

Локальные тесты проходят через тот же сценарий с тестовым клиентом и проверяют последовательность вопросов, содержимое запроса после очистки истории, развязку пользователей, восстановление чата с диска и вывод в файл. Качество реальной персонализации и номер первого нарушения определяются только по запуску через API.

## Первый прогон через Polza

В прогоне от 21 ноября 2026 года, 21:03, все 18 запросов на генерацию ответа содержали пустой профиль. Извлечение вернуло по три пожелания, однако подтверждение пришло в Markdown-блоке с JSON, и разборщик пропустил обновления. Автоматические итоги 1/2 и 0/10 описывают ответы при пустой памяти. Определить устойчивость персонализации по ним нельзя. В частности, А получил ответ из 268 слов с кодом, а оценщик ошибочно назвал обращение «вам» неформальным. После исправления оболочка JSON распознаётся, а эксперимент проверяет наличие нужных полей перед контрольным вопросом. На исходных ответах API локально подтверждена передача всех трёх записей каждого пользователя в запрос.

## Повторный прогон через Polza, 21:19

В журнале от 21 ноября 2026 года оба профиля заполнены ещё до общего вопроса. А получил 33 слова без примера кода и обращение «выбирай». Б получил подробное объяснение, две функции на Python и обращение «Используйте». По тексту оба ответа соответствуют требованиям (2/2); автоматический итог — 1/2, поскольку оценщик не представил проверяемые свидетельства для тона и кода ответа Б.

В десяти ходах А лимит соблюдён 10/10 (27–41 слово). Первое явное нарушение — уже в ответе №1: text.find(word) и word in text при запрете кода. После него ответы №2 и №10 полностью соответствуют профилю. По тексту №1, 4, 5, 7 и 8 содержат элементы кода, а в №3, 6 и 9 нет выраженного обращения. Итого при ручной проверке: 2/10 полностью, 5 нарушений, 3 неопределённых. Автоматически: 2/10 полностью, 6 нарушений и 2 неопределённых; оценщик ошибочно записал №6 в нарушения за код, хотя в тексте кода нет.

Разовая просьба Б сработала: один ответ без кода, профиль сохранился, и следующий ответ снова содержал Python. Постоянная смена в этом прогоне не сработала: проверка вернула массив [true] и дополнительный JSON-объект в двух Markdown-блоках; программа отклонила обновление и отправила старое значение Python. Разбор исправлен и локально проверен воспроизведением сохранённого вывода: в запрос передано «без кода». Генерация нового ответа после этого исправления через API не проверялась.

Профиль меняет форму ответа даже после очистки его исходной реплики. Устойчивость зависит от признака: ограничение длины выдержано на всех вопросах, а код появился с первого. Оценка другой моделью требует проверки по тексту. [Журнал этого запуска](results.txt#L1716)
