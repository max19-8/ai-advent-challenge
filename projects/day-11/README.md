# День 11. Модель памяти ассистента

Цель опыта — выяснить, откуда ассистент берёт сведения для ответа, как долго они остаются доступны и сколько места занимают в запросе.

## Запуск

Из корня репозитория, с Python и ключом `POLZA_API_KEY` в корневом `.env`:

```sh
python -m pip install -r projects/day-11/requirements.txt
python projects/day-11/main.py chat
python projects/day-11/main.py experiment
```

В чате напишите обычное сообщение, например «Обычно я читаю отчёты в PDF. Для этой встречи сделай слайды». После ответа введите `/memory`, чтобы увидеть результат извлечения. Команда `/task ИМЯ` переключает задачу и начинает для неё свежий диалог. При возврате восстанавливаются рабочие записи. Команда `/new` начинает новый диалог в той же задаче, `/clear short|working|facts` очищает выбранный слой, `/exit` завершает программу. При повторном запуске чат продолжится с последнего сохранённого хода.

Эксперимент начинает с пустой памяти и не затрагивает чат. Оба режима дублируют вывод в консоль и файл. Журнал эксперимента — [results.txt](results.txt), чата — `state/chat.txt`. Новый запуск дописывается с отметкой времени. Путь журнала можно изменить параметром `--report ПУТЬ`. Первый запуск токенизатора загружает словарь и шаблон Qwen, дальнейшие измерения используют локальный кеш.

## Запись и чтение памяти

| Слой | Правило записи | Что видит модель при ответе |
| --- | --- | --- |
| Краткосрочная, `short` | После успешного ответа записываются обе реплики. Сохраняются три последние пары. | Дословные реплики в исходном порядке. |
| Рабочая, `working` | Извлекаются договорённости и ограничения конкретной задачи. При исправлении модель должна предложить прежний ключ и новое значение. | Все актуальные пары ключ–значение только активной задачи. |
| Долговременная, `facts` | Извлекаются явно выраженные устойчивые сведения, привычки и решения, которые распространяются на другие задачи. | Все сохранённые факты пользователя. Правило текущей задачи может уточнять общее предпочтение. |

Как в [StickyFacts дня 10](../day-10/agent.py), модель извлекает данные из естественной речи и возвращает JSON. Теперь она предлагает изменения отдельно для двух словарей. Для каждого изменения нужна цитата из новой реплики. Пустые списки допустимы. Программа проверяет поля и наличие цитаты без учёта регистра, применяет изменения к копии памяти и по ней запрашивает ответ. Только после успешного ответа ход сохраняется целиком. Проверка цитаты подтверждает её происхождение. Перед записью модель отдельным запросом оценивает, подтверждает ли пользователь значение и выбранный слой. Решения по кандидатам выводятся в журнал. Этот шаг тоже может ошибаться. При ответе активные записи и вопрос передаются вместе, после истории диалога.

Слои хранятся раздельными полями одного JSON-снимка, рабочие записи сгруппированы по имени задачи. Это позволяет сохранить весь ход одним атомарным обновлением файла. Название активной задачи входит в базовую часть запроса. Эталоны эксперимента доступны только программе проверки.

## Как устроен опыт

1. Пользователь сообщает предпочтительное обращение и шифр макета в одной реплике, затем исправляет шифр. Вопрос о бумаге и благодарность проверяют, появятся ли лишние записи.
2. Несколько коротких реплик вытесняют первые сообщения из короткого окна. Одноразовый маркер в последнем ответе даёт отдельный вопрос для проверки истории.
3. На независимых копиях общего снимка задаются одни и те же три вопроса: со всеми слоями, без каждого по отдельности и с полностью очищенной памятью. Проверочные ответы в память не попадают. Ещё шесть вопросов проверяют переключение задач, возврат и загрузку JSON с началом нового диалога.
4. Для фиксированного вопроса локальный токенизатор дня 10 считает сериализованный запрос с шаблоном чата. Сначала измеряется база, затем по очереди добавляются `facts`, `working`, `short`. Разница соседних измерений включает заголовки блоков и границы сообщений. Для реальных обращений отдельно выводятся вход и выход из API usage. Обычная реплика требует запросов извлечения и ответа. Если после проверки цитат остались кандидаты, между ними выполняется отдельный запрос verify. Он получает новую реплику с контекстом и оценивает каждое предложение записи. Пустой список кандидатов пропускает этот шаг. Проверочный вопрос требует одного.

## Что удалось измерить

Локальные проверки запускаются командой `python projects/day-11/test_memory.py -v`. В них клиент возвращает заданные ответы, а хранение, сборка запроса и токенизатор работают как в чате. Для вопроса «Что известно?» получены такие размеры:

| Состав запроса | Всего токенов | Добавлено |
| --- | ---: | ---: |
| База | 188 | — |
| С долговременным предпочтением | 203 | 15 |
| С добавлением условия задачи | 222 | 19 |
| С добавлением последней пары реплик | 254 | 32 |

После независимой очистки из текста запроса исчезало соответствующее значение: «янтарь» из профиля, «кобальт» из задачи, «Капля-39» из диалога. В каждом случае два оставшихся значения были доступны. В этом состоянии история с одной парой реплик стоила 32 токена, а один факт — 15. Эти цифры зависят от текста, окна и используемого шаблона.

При переключении задач тест подтвердил сохранность профиля и восстановление рабочего словаря после загрузки. Запись с неподтверждённой цитатой пропускается с указанием причины. Остальные подтверждённые записи обрабатываются, диалог продолжается. При повреждённом JSON пропускается обновление словарей за ход. Сбой при получении самого ответа оставляет снимок целым.

## Результаты прогона Qwen через Polza

21 ноября 2026 года в 19:54 эксперимент прошёл до конца на версии до добавления verify и переноса профиля в сообщение с вопросом. В 19 из 21 контрольного ответа результат совпал с ожиданием. Оценка допускает различия в регистре и конечной пунктуации. Ошибки при извлечении записей проверялись отдельно. [Полный журнал](results.txt#L70)

Из одной реплики модель записала «Радан» в профиль, а цель и шифр макета — в рабочую память. Исправление заменило «Тополь-47» на «Липа-83». Благодарность оставила оба словаря без изменений. В коротком окне к моменту проверки находились три последние пары реплик, включая ответ «Звон731». Каждый из трёх эталонов встречался только в своём слое.

| Условия | Как ко мне обращаться? | Какой шифр макета? | Каким был последний ответ? |
| --- | --- | --- | --- |
| Полная память | Радан | Липа-83 | Звон731 |
| Без профиля | Нет данных | Липа-83 | Звон731 |
| Без рабочей памяти | Нет данных | Нет данных | Звон731 |
| Без короткого окна | Радан | Липа-83 | Нет данных |
| Все слои очищены | Нет данных | Нет данных | Нет данных |

При переключении на экскурсию шифр макета стал недоступен. После возврата в задачу модель снова назвала «Липа-83». Загрузка снимка из JSON с очисткой истории сохранила имя и шифр; повторить прежний ответ модель уже не смогла.

Оба расхождения касались имени. После удаления рабочей памяти и после переключения на экскурсию в промпте оставался профиль с именем «Радан», однако модель ответила «Нет данных». Значит, приложение сохранило и передало факт, а модель в этих двух запросах его не использовала. Почему именно так изменился ответ, один прогон установить не позволяет.

Отдельная ошибка произошла при записи: из вопроса «Мы уже выбрали тип бумаги для печати?» модель вывела «тип бумаги — не выбран». Пользователь такого решения не сообщал. Цитата подлинная, но не подтверждает вывод. В этом прогоне уточнённая инструкция не предотвратила ошибку, и ассистент повторил её в ответе.

Для вопроса об обращении локальный токенизатор насчитал 178 токенов без памяти. Профиль добавил 23, рабочая память 70, история 108; полный запрос занял 379 токенов локально. Провайдер сообщил 174 входных токена без памяти и 365 с полной памятью. Разбиение по слоям выше относится к локальному шаблону.

| Назначение вызова | Запросов | Вход API, токены | Выход API, токены |
| --- | ---: | ---: | ---: |
| Извлечение из обычных реплик | 8 | 4783 | 246 |
| Ответы в диалоге | 8 | 2902 | 128 |
| Контрольные вопросы | 21 | 5809 | 90 |

В этом диалоге обслуживание памяти потребовало больше входных токенов, чем восемь ответов пользователю. Качество записи и качество чтения тоже пришлось оценивать отдельно: модель может сохранить необоснованный вывод или пропустить верный факт, который есть в запросе.

## Повторный прогон после изменения промпта и добавления verify

Прогон 19:59 завершён. Совпало 18 из 21 контрольного ответа (прежде 19 из 21). Три расхождения относятся к одному вопросу о последней реплике. Ошибка записи о бумаге оценивается отдельно от этих 21 ответов. [Журнал повторного прогона](results.txt#L342)

| Проверка | 19:54 | 19:59 |
| --- | --- | --- |
| Имя после очистки рабочей памяти и в другой задаче | В обоих случаях «Нет данных» | В обоих случаях «Радан» |
| Повтор последнего ответа при доступной истории (все слои, без профиля, без рабочей памяти) | Во всех трёх случаях «Звон731» | Во всех трёх случаях «Нет данных» |
| Вопрос пользователя о выборе бумаги | Сохранено «не выбран» | Сохранено «не выбран», verify одобрил запись |
| Доступность шифра макета | Зависит от активной задачи и её рабочей памяти | То же; после возврата восстановлен «Липа-83» |

Маркер «Звон731» находился в коротком окне и был передан модели. Она не воспроизвела его даже при всех слоях. В новом прогоне эффект удаления истории для этого вопроса измерить нельзя: правильного исходного ответа не было. Изменилось сразу несколько элементов промпта; причину различия по двум запускам установить нельзя.

Для вопроса об обращении база заняла 224 токена; профиль добавил 15, рабочие записи 52, история 108. Итого 399 токенов, столько же сообщил API. За восемь реплик проверка смысла вызывалась трижды и потребовала 1408 входных и 13 выходных токенов. Она приняла все предложенные записи, включая ошибочную. Отсутствие сведений о решении модель дважды истолковала как сведения об отсутствии решения — при извлечении и при проверке.

Оба прогона подтверждают изоляцию хранилищ, исправление шифра и восстановление задачи. Отдельно нужно оценивать обоснованность записи, доступность записи в промпте и способность модели использовать её в ответе. В этом сравнении чтение профиля улучшилось, чтение истории ухудшилось, а дополнительная проверка расходовала токены без наблюдаемого выигрыша на примере с бумагой.
