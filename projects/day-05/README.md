# День 5. Версии моделей

Пять задач из дня 3 × три модели — **15 запросов** через Polza.

| Категория | Модель | API ID |
| --- | --- | --- |
| Маленькая | Qwen2.5 7B Instruct | `qwen/qwen-2.5-7b-instruct` |
| Средняя | Llama 3.3 70B Instruct | `meta-llama/llama-3.3-70b-instruct` |
| Флагманская | Opus 5.5 | `anthropic/claude-opus-5.5` |

[Модели и цены Polza](https://polza.ai/models). Qwen 7B — компактная модель,
Llama 70B — более крупная модель среднего уровня в нашей выборке, Opus —
флагманская модель Claude. Правильность на наших задачах проверяем экспериментом.

В запросе только `model` и `messages`: исходное условие без дополнительных инструкций.
Параметры reasoning, температуры и лимитов не задаём. Настройки по умолчанию могут
различаться; сравниваем модели в штатных режимах. Провайдера выбирает Polza,
фактически возвращённые модель и провайдер записываются в отчёт, если API их указал.
Каждое обращение — новый контекст. Порядок: задача → Qwen → Llama → Opus.
HTTP-таймаутов и автоматических повторов нет; отдельные ответы могут занимать минуты.

## Запуск

Из этой рабочей копии с общим `.env` и `POLZA_API_KEY`:

```bash
source .venv/bin/activate
python projects/day-05/main.py
```

Ответы, ID генераций, завершение, токены, время и стоимость сохраняются обычным
текстом в `results.txt` до и после каждого запроса. При Ctrl+C остаются частичные
результаты. Продолжить с первой незавершённой комбинации:

```bash
python projects/day-05/main.py --resume
```

Готовые ответы пропускаются, неполученные и обрезанные повторяются. Обычный запуск
начинает эксперимент заново. Перед заменой существующий отчёт копируется в соседнюю
папку `ai-advent-challenge-archive/day-05/`. После прерывания статус запроса
на сервере может отличаться от локального; повтор — новое оплачиваемое обращение.

## Разбор

Задачи и проверенные эталоны находятся в `TASKS` в `main.py`; модели эталоны не получают.
Вручную сверяем итоговые ответы: рыцари — Анна и Вера лжецы, Борис рыцарь;
мост — 27 минут; рюкзак — 46; маршрут — 10,5; вероятность — 15/68.
Ошибки объяснения отмечаем отдельно от правильности итогового ответа.

Время — весь HTTP-запрос до получения тела ответа, включая сеть и ожидание сервиса.
Токены берём из usage; reasoning входит в выходные и повторно не прибавляется.
Стоимость — фактически списанная сумма из `usage.cost_rub` (или его алиаса `cost`),
[по документации Polza](https://polza.ai/docs/osobennosti/usage). Тарифами вручную её
не заменяем. Отсутствующие метрики — `н/д`, а не ноль. Все попытки входят в расходы;
если данные хотя бы одной отсутствуют, соответствующая сумма неизвестна.

Для получения новых ответов по частям:

```bash
python projects/day-05/main.py --resume --stream
```

`--stream` добавляет только `stream=true` и `stream_options.include_usage=true`.
Это режим доставки; настройки генерации остаются по умолчанию. Консоль показывает
поступление SSE-событий, ID генерации сохраняется после первого события с ID.
Текст собирается до `[DONE]`, usage и стоимость берутся из завершающих событий.
Режим отмечается у каждого обращения. Время обычной и потоковой доставки может
отличаться. Без этого флага payload по-прежнему содержит только `model` и `messages`.

## Ответы и ошибки

| Задача | Эталон | Qwen 7B | Llama 70B | Opus |
| --- | --- | --- | --- | --- |
| Рыцари и лжецы | Анна и Вера — лжецы, Борис — рыцарь | Итог верен, объяснение противоречиво | Неверно: Анна и Вера — рыцари, Борис — лжец | Верно |
| Мост | 27 минут | 27 — итог верен, схема неверная | 27 — итог верен, схема неверная | 27 и схема верны |
| Рюкзак | 46, A+C+F | 46 — верно | 43 — неверно | 46 — верно |
| Маршрут с купоном | 10,5 | 7 — неверно | 10,5 — верно | 10,5 — верно |
| Условная вероятность | 15/68 | 15/34 — неверно | 15/68 — верно | 15/68 — верно |

**Qwen: 3/5 по итоговому ответу.** Верно называет типы рыцарей, число 27 для моста
и ценность 46 для рюкзака. На рыцарях объяснение сначала правильно выводит, что
Вера — лжец, затем неверно трактует её ложное высказывание как доказательство,
что Анна — рыцарь, но всё равно заканчивает правильным итогом.
В задаче про мост человек со временем 7 минут уже перешёл в третьем шаге,
а в последнем шаге модель снова отправляет его с исходного берега.
В маршруте Qwen уменьшает на 50% стоимость всего пути, хотя купон действует
только на одно прохождение ребра: 14/2 = 7 вместо правильных 10,5.
В вероятности модель смешивает цвета шаров и получает неверный числитель.

**Llama: 3/5 по итоговому ответу.** Верны число 27 для моста, стоимость 10,5
для маршрута и вероятность 15/68. На рыцарях модель выбирает противоречивое
распределение типов. В рюкзаке жадно берёт два самых ценных предмета F и E,
получает 43 и не находит лучший набор A+C+F с ценностью 46.
На мосте человек со временем 2 минуты возвращается в четвёртом шаге,
но больше не переходит; модель ошибочно объявляет переправу завершённой.

**Правильное число не гарантирует правильность решения.** Основная таблица
следует оценке итогового ответа. Если дополнительно требовать корректное
объяснение без указанных противоречий и допустимую схему переходов,
Qwen получает **1/5**, Llama — **2/5**, Opus — **5/5**.

**Opus: 5/5.** Итоги совпали с эталонами, указанные выше нарушения условий
не встретились. Модель дала допустимую переправу за 27 минут, набор A+C+F,
сравнила два случая применения купона — до C и после C — и корректно
вычислила условную вероятность 30/136 = 15/68.

## Выводы

**По итоговым ответам:** Qwen — 60%, Llama — 60%, Opus — 100%.
Флагман точнее обеих младших моделей на **40 процентных пунктов**, то есть
решил на две задачи больше. При проверке качества объяснения разница заметнее.
Размер модели сам по себе не обеспечил преимущество: у Qwen 7B и Llama 70B
одинаковое число верных итогов, но разные успешные задачи и ошибки.

**Opus дороже Qwen в 108,44 раза:** 10,05004360 ₽ против 0,09268151 ₽.
Llama стоит 0,24534331 ₽. Более дорогая модель в этом прогоне оправдала затраты
там, где важно одновременно получить правильный итог и соблюсти условия задачи.

**Где хватило маленькой модели:** Qwen справилась с рюкзаком — получила 46
и выбрала A+C+F. В рыцарях и мосте её итог совпал с эталоном, но объяснение
потребовало исправлений, поэтому считать эти решения надёжными нельзя.
Llama верно решила маршрут с купоном и условную вероятность, но допустила
ошибки на других задачах. Дешёвая модель может быть исходным вариантом,
если её ответ можно проверить; уверенная формулировка сама по себе не заменяет проверку.

**Скорость и ресурсы:** Qwen быстрее всех по сумме пяти обращений — 30,24 с,
Llama — 38,28 с, Opus — 45,40 с. Меньше всего токенов использовала Llama,
но дешевле всего оказалась Qwen. Reasoning-токены появились только у Opus;
мы не задавали этот режим, а сравнивали модели с настройками по умолчанию.
