# День 6. Первый агент

CLI-агент на Python: принимает вопрос, обращается к LLM через Polza.ai, выполняет
выбранные моделью инструменты и возвращает их результаты модели до финального ответа.
Модель — `deepseek/deepseek-v4-flash`, reasoning отключён. Провайдер выбирается Polza;
результаты сохраняются обычным текстом в `results.txt`.

## Как работает агент

В дне 1 программа один раз отправляла вопрос и печатала ответ. Здесь класс `Agent`
управляет циклом, в котором ответ модели может быть запросом на выполнение функции.
Функции выполняются локально, а не на стороне LLM.

```text
Скрипт берёт вопрос из QUESTIONS
          ↓
Agent отправляет историю + схемы инструментов в LLM
          ↓
Модель запросила инструмент? ── нет ──→ сохранить финальный ответ
          │ да
          ↓
Agent проверяет аргументы и вызывает Python-функцию
          ↓
Добавляет результат в историю и снова обращается к LLM
```

Каждый HTTP-запрос содержит:

- `messages`: короткую инструкцию `system`, вопрос пользователя и накопленную
  историю текущего вопроса;
- `tools`: JSON Schema двух функций — названия, описания и допустимые аргументы;
- `tool_choice: "auto"`: модель сама выбирает, нужен ли вызов, какую функцию вызвать
  и с какими аргументами;
- `reasoning: {"enabled": false}`: отключение отдельного режима рассуждений.

**Системный промпт задаёт правила поведения.** Он просит получать учебные курсы
через инструмент, выполнять арифметику калькулятором, не выдумывать результаты
и отвечать сразу, если инструменты не нужны. Последовательность конкретных вызовов
не прописывается. Для самого протокола tool calling сообщение `system` необязательно;
в этом задании оно помогает задать назначение агента.

**Схемы инструментов передаются отдельно от промпта.** Исходный Python-код функций
модель не получает. В ответ она может вернуть `tool_calls`: идентификатор вызова,
имя функции и аргументы в виде JSON-строки. Агент выбирает функцию только из своего
реестра, проверяет аргументы по схеме и выполняет её.

В историю добавляются исходное сообщение `assistant` с вызовами и сообщение `tool`
для каждого результата. Поле `tool_call_id` связывает результат с конкретным вызовом.
Следующее обращение к модели содержит эту историю, поэтому она может использовать
результат в следующем вычислении или финальном ответе.

За один ответ модель может запросить несколько функций. Агент выполняет их
последовательно и возвращает все результаты перед следующим обращением к LLM.
Это один раунд, а не несколько зависимых шагов. В зависимой цепочке модель сначала
получает результат одной функции, затем в следующем раунде выбирает аргументы другой.

## Что реализовано

| Компонент | Ответственность |
| --- | --- |
| `Agent.run` | Новый контекст вопроса, цикл запросов и инструментов, финальный ответ |
| `Agent.request` | HTTP-запрос с историей и схемами, проверка ответа API |
| `Agent.execute_tool` | Проверка имени и аргументов, вызов разрешённой функции |
| `main` | Прогон трёх вопросов из `QUESTIONS`, сохранение вопросов и ответов |

| Инструмент | Аргументы | Результат |
| --- | --- | --- |
| `get_exchange_rate` | `from_currency`, `to_currency`: RUB, USD или EUR | Число единиц целевой валюты за одну исходной |
| `calculate` | `operation`: add/subtract/multiply/divide; числа `a`, `b` | Результат одной операции |

Учебные курсы зашиты внутри функции: **1 USD = 90 RUB, 1 EUR = 100 RUB**.
Остальные пары получаются из этих соотношений; одинаковые валюты дают курс 1.
Это не рыночные данные. Калькулятор использует обычную арифметику Python, без `eval`;
расчёты с дробными числами имеют стандартные ограничения точности `float`.

Неизвестная функция, неправильные аргументы, деление на ноль и неконечные числа
возвращаются модели как результат с полем `error`. Она может исправить вызов или
объяснить ограничение. Ошибки HTTP, сети, структуры протокола и обрезанные ответы
завершают текущий вопрос с явным сообщением; прогон продолжается со следующим вопросом.

Предел — **8 обращений к LLM на вопрос**, не более 16 вызовов инструментов в одном
ответе. Если модель не дала финального ответа, достижение предела считается ошибкой,
а не успешным завершением. Таймаут соединения — 10 секунд, ожидания чтения — 180 секунд;
это не общий предел длительности вопроса. Автоматических повторов запросов нет.

## Запуск

Из корня репозитория с существующим `POLZA_API_KEY` в общем `.env`:

```bash
cd ~/Projects/ai-advent-challenge
source .venv/bin/activate
python -m pip install -r requirements.txt
python projects/day-06/main.py
```

Скрипт сам выполняет три вопроса из `QUESTIONS` в `main.py`, вводить ничего не нужно.
Вопросы и финальные ответы дописываются в `results.txt`. Отладочного вывода
в консоль нет. После третьего вопроса скрипт завершается.
Остановить прогон можно сочетанием Ctrl+C.

Каждый новый вопрос начинает отдельный контекст. Это CLI для независимых запросов,
а не диалог с памятью между вопросами. При Ctrl+C уже записанные ответы сохраняются;
продолжение незавершённого вопроса не реализовано. Если запрос уже был отправлен,
прерывание локального клиента не гарантирует отмену обработки и списания на сервере.

## Проверка трёх сценариев

В коде зашиты и последовательно выполняются:

1. `Объясни простыми словами, что такое API.`
2. `Какой учебный курс USD к RUB задан в программе?`
3. `Переведи 250 долларов в рубли по учебному курсу.`

| Сценарий | Ожидаемое поведение | Ожидаемое число обращений к LLM |
| --- | --- | --- |
| Без инструментов | Сразу текстовое объяснение | 1 |
| Один инструмент | `get_exchange_rate(USD, RUB)` → ответ о курсе 90 | 2 |
| Два зависимых инструмента | Получение курса → `calculate(multiply, 250, 90)` → ответ о 22 500 RUB | 3 |

Это ожидания, а не записанные результаты. Число запросов может отличаться:
поведение выбирает модель.
Три вопроса не означают три HTTP-запроса: при ожидаемом поведении их будет шесть
(1 + 2 + 3), поскольку после выполнения инструментов агент снова обращается к модели.
Для третьего сценария важно, чтобы калькулятор был вызван в следующем раунде
после получения курса. Два вызова в одном сообщении не доказывают эту зависимость.
Правильный текст без нужной цепочки тоже не подтверждает выполнение сценария.

## Формат результатов

`results.txt` содержит только вопросы и финальные ответы обычным текстом:

```text
Вопрос:
Какой учебный курс USD к RUB задан в программе?

Ответ:
В программе задан фиксированный учебный курс: **1 USD = 90 RUB**.
```

Новые результаты дописываются в конец файла. Если вопрос не удалось завершить,
вместо ответа сохраняется сообщение об ошибке. JSON-запросы, технические события
и промежуточные вызовы в этот файл не записываются.

длительностей HTTP-запросов, включая сеть и ожидание сервиса, не чистая генерация.

Подтверждённая цепочка третьего сценария:

```text
LLM, шаг 1: get_exchange_rate(from_currency="USD", to_currency="RUB")
Python: rate = 90.0
LLM, шаг 2: calculate(operation="multiply", a=250, b=90)
Python: result = 22500
LLM, шаг 3: «250 долларов США ... равны 22 500 рублей»
```

В запросе второго шага уже есть результат курса с правильным `tool_call_id`.
В запросе третьего шага сохранены оба вызова и оба результата. Значит, это два
зависимых раунда, а не два инструмента, запрошенные одновременно. Каждый вопрос
начинается с новых `system` и `user`, без истории предыдущего сценария.

Таблица и последовательность вызовов зафиксированы при разборе исходного отладочного
прогона. Для публикации в `results.txt` оставлены только три вопроса и их исходные
финальные ответы. Текущая версия скрипта не собирает технический журнал и метрики.

## Выводы

- **Все три сценария задания подтверждены трассой:** без инструментов, с одним
  инструментом и с двумя последовательными инструментами.
- **Решение о вызове пришло от модели.** Во всех запросах стояло `tool_choice: auto`;
  агент не выбирал инструменты по тексту вопроса. Общие правила выбора при этом
  заданы системным промптом и описаниями функций — самостоятельность модели
  проверялась в этих условиях, а не без инструкций.
- **Модель использовала результаты локального кода.** Значение курса 90 не передано
  в исходном вопросе или схемах. Оно получено из функции, затем появилось в аргументах
  калькулятора. Финальная сумма совпала с его результатом.
- **Агент — это цикл с контекстом.** Одна пользовательская задача потребовала трёх
  обращений к LLM: выбрать первый инструмент, выбрать второй после получения данных,
  сформулировать ответ после вычисления.
- **Число шагов само по себе не определяет время и стоимость.** В этом прогоне
  длинное объяснение API заняло больше времени, чем три коротких обращения для
  конвертации. Это наблюдение одного прогона, а не гарантия скорости или надёжности
  на других запросах. Повторные прогоны и ошибки реальных инструментов не проверялись.
