# День 2. Формат ответа

Один вопрос, пять способов управления ответом, по три повтора: **15 запросов**.
Модель — `deepseek/deepseek-v4-flash` через Polza.ai.

> Расскажи о планете Марс: укажи её порядковый номер от Солнца,
> назови естественные спутники и кратко опиши поверхность.

| Вариант | Условия | Что сравниваем |
| --- | --- | --- |
| Обычный ответ | Только основной вопрос | Как модель сама выбирает оформление и объём |
| Формат словами | Просьба вернуть JSON с полями `planet`, `position`, `satellites`, `surface` | Соблюдение инструкции и разбор кодом |
| Лимит токенов | Только основной вопрос и `max_tokens=50`, без требования JSON | Объём, завершённость и потерю содержания |
| Stop sequence | Маркер после номера планеты, перед спутниками и поверхностью; `stop=["<<<END>>>"]` | Где остановился текст и какие сведения не попали в ответ |
| Строгая схема | Основной вопрос и JSON Schema через `response_format`, `strict=true` | Работу параметра API, типы полей и разбор кодом |

В stop-варианте к основному вопросу добавляется инструкция:

> Сначала укажи название планеты и её порядковый номер от Солнца.
> Затем на отдельной строке напиши маркер <<<END>>>.
> После маркера назови естественные спутники и кратко опиши поверхность.

Так маркер находится в середине запрошенного ответа. Проверяем, останется ли
только часть до маркера, а спутники и описание поверхности не попадут в выдачу.
Сам маркер при срабатывании stop не должен возвращаться. Если модель не соблюдёт
инструкцию или маркер останется в тексте, фиксируем фактический результат.
Отдельного контрольного запроса с тем же промптом без stop в этом прогоне нет.

JSON нужен только в двух вариантах: формат словами и строгая схема.
`planet` и `surface` — строки, `position` — целое число, `satellites` — массив
строк. Все поля обязательны, дополнительные запрещены. Весь текст проверяется
через `json.loads`, затем через `jsonschema`, без удаления Markdown и исправлений.
Для остальных вариантов проверка JSON не выполняется; в таблице стоит «—».
Схема управляет структурой, но не гарантирует правильность фактов.

Во всех запросах закреплён `streamlake/fp8`, переключение на других провайдеров
отключено. Рассуждения отключены через `reasoning.enabled=false`.
Температура и остальные параметры генерации не задаются. Только вариант
с лимитом содержит `max_tokens=50`; в остальных действует бюджет сервиса.
HTTP-таймаут не задан. Нет истории, системного промпта и автоматических повторов.

Порядок в каждом раунде: схема → обычный ответ → формат словами → лимит → stop.
Первый запрос со схемой входит в общие 15. Ошибка сети/API останавливает прогон,
обрезание по лимиту — нет. Пустой текст с `finish_reason=length` также сохраняется.

## Запуск

Из корня репозитория с ключом `POLZA_API_KEY` в общем `.env`:

```bash
source .venv/bin/activate
python -m pip install -r requirements.txt
python projects/day-02/main.py
```

Программа печатает полные ответы, завершение и число выходных токенов.
Проверки JSON/схемы показываются для двух JSON-вариантов, наличие маркера — для stop.
В конце выводится сводка. Ограничение токенов оцениваем по тому, закончен ли
ответ и какие из запрошенных сведений успела выдать модель.

`results.json` содержит отправленные параметры, исходные ответы API, тексты,
usage, причины завершения и проверки (`checks=null`, если JSON не запрашивался).
Данные сохраняются до и после каждого обращения, в том числе при Ctrl+C.
Каждый запуск заменяет `results.json`; нужный предыдущий прогон сохрани отдельно.
Ключ не записывается в payload и результаты, его совпадения в ответах маскируются.
Поле фактического провайдера сохраняется, если API его возвращает.

## Сравнение и выводы

Прогон с маркером в середине ответа (`stop-middle-v1`):
**2026-11-07 20:48:36 UTC**, полные ответы — в [`results.json`](results.json).
Все 15 запросов завершились с HTTP 200, ошибок API и пустых итоговых текстов нет.
Во всех ответах `reasoning_tokens=0`. Провайдер закреплён в запросах,
но API не вернул поле фактического провайдера.

| Вариант | Выходные токены по повторам | Результат |
| --- | --- | --- |
| Обычный ответ | 268, 276, 317 | Текст со списками и Markdown, все три части вопроса раскрыты |
| Формат словами | 102, 91, 81 | 3/3 JSON-объекта разбираются кодом и соответствуют нужной структуре |
| Только max_tokens=50 | 50, 50, 50 | 3/3 ответа оборвались, `finish_reason=length` |
| Stop sequence | 20, 20, 20 | 3/3 ответа содержат только название планеты и номер, `finish_reason=stop` |
| Строгая JSON Schema | 155, 177, 144 | API принял схему; 3/3 JSON-объекта разбираются кодом и проходят валидацию |

**Без ограничений модель сама выбирает оформление и объём.** Просьба «кратко»
не задала точную длину: получились разные списки и описания на 268–317 токенов.
Этот вариант служит точкой отсчёта для остальных; проверять его на JSON не требуется.

**Инструкция формата влияет на ответ через текст запроса.** Все три ответа
содержат только объект с четырьмя полями, без вступлений и Markdown. Они заметно
короче обычных ответов — 81–102 токена, в том числе за счёт более короткого
описания поверхности. Это наблюдение нашего прогона, а не обещание, что требование
JSON всегда сокращает ответ. Здесь модель соблюла инструкцию во всех трёх повторах.

**max_tokens ограничивает генерацию, но не учит модель укладываться в бюджет.**
Все три ответа использовали ровно 50 токенов и не раскрыли вопрос целиком.
Повтор 1 закончился на `2.  **Естественные сп`, повтор 2 — на `(в перевод`,
повтор 3 — на `Меркурия, Вен`. Во всех случаях описание поверхности отсутствует.
Лимит сработал как жёсткий потолок и может оборвать слово или Markdown-разметку.
Если нужен короткий законченный ответ, желаемую краткость стоит описывать
в инструкции, а бюджет выбирать с запасом; один max_tokens этого не обеспечивает.

**Stop останавливает выдачу на заданной последовательности, а не на числе токенов.**
Во всех трёх повторах итоговый текст после удаления краевых пробелов одинаков:

```text
Марс — четвёртая планета от Солнца.
```

Маркер `<<<END>>>`, спутники и описание поверхности отсутствуют. Ответ сохранил
законченную первую фразу и занял 20 токенов, хотя лимит 50 в этом варианте не задан.
Это соответствует ожидаемой остановке перед маркером: стоп-строка не включается
в выдачу, а запрошенное продолжение после неё не возвращается. Так можно задать
смысловую границу, но не обязательно получить полный ответ на исходный вопрос.
API вернул общее `finish_reason=stop`, без отдельного `stop_reason`;
контрольного запроса с тем же промптом без stop не было, поэтому причину
остановки выводим по наблюдаемому тексту, а не по отдельному подтверждению сервиса.

**Строгая схема задаёт структуру через параметр API.** Все три запроса со схемой
приняты, ответы содержат требуемые поля и типы без лишних полей. В отличие от
инструкции словами, структура передаётся отдельным объектом `response_format`.
Схема не ограничивает длину строки `surface`: ответы заняли 144–177 токенов,
а описания поверхности оказались подробнее, чем в варианте с текстовой инструкцией.

**Разбор кодом проверен для двух JSON-вариантов.** Все шесть текстов целиком
прошли `json.loads` и JSON Schema без исправлений. `position` получен как целое
число 4, `satellites` — массив строк с Фобосом и Деймосом, `planet` — строка «Марс».
Остальные варианты JSON не запрашивали, их содержание и завершённость оцениваются
отдельно. Структура данных не подтверждает истинность всех фактов в описании.

**Итог:** инструкция словами помогает управлять оформлением; схема позволяет
описать поля и типы для программы; max_tokens ограничивает расход выходных токенов;
stop задаёт строку, на которой прекращается выдача. В нашем прогоне лимит оборвал
текст посреди фразы, а stop сохранил выбранную первую фразу и отсёк продолжение.
Оба JSON-варианта дали по 3/3 подходящих объекта — превосходства схемы над
инструкцией по частоте успешных ответов эта выборка не показала.
Три повтора одного вопроса характеризуют этот эксперимент, не все будущие запросы.

Предыдущий полный прогон сохранён отдельно:
[`results-stop-at-end-20261107T203347Z.json`](results-stop-at-end-20261107T203347Z.json).
В нём инструкция JSON и строгая схема дали по 3 подходящих объекта из 3,
а лимит 50 токенов оборвал все три ответа. Маркер stop стоял в конце и не позволил
наглядно увидеть отсечение части ответа. Новые результаты с ним не смешиваем.

Факты проверяем отдельно: Марс — четвёртая планета от Солнца, спутники — Фобос
и Деймос. Эти сведения не подставляются в запрос как готовый ответ.
